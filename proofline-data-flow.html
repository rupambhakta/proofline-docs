Every node,
one line each

Your side

  • You: answer cards and make the final calls
  • Code + PR: your repo; a pull request starts a run
  • Docs + tickets: specs and stories the Planner reads
  • Recorder: records real sessions and network traffic
  • Your app: the URL or build under test

Surfaces

  • Approvals inbox: one-click cards with the evidence attached
  • Dashboard: results, trends and release readiness
  • GitHub app: PR checks, comments and fix PRs
  • Tickets + chat: bug reports and alerts in Jira, Linear, Slack
  • CLI + IDE: start a run from the terminal or Claude Code
  • Orchestrator: starts every job, enforces budgets and approvals, keeps the audit log

AI workers

  • Mapper: builds the App Model from code, recordings and traffic
  • Planner: picks what to test, riskiest first
  • Writer: writes tests at the cheapest level that works
  • Reviewer: checks the Writer's tests on a different model
  • Data builder: makes the test data each test needs
  • Env builder: builds the throwaway sandbox
  • Selector: picks only the tests a change affects
  • Triager: names the cause of each failure
  • Maintainer: repairs tests after an intended change
  • Reporter: turns verdicts into comments, tickets and reports

AI gateway

  • PII redaction: removes personal data before any model call
  • Injection guard: app content is data, never instructions
  • Context cache: same question and context, saved answer
  • Model router: smallest model that can do the job
  • Eval harness: scores every worker on known answers

Knowledge

  • App Model: screens, endpoints, data and roles
  • Intent Ledger: behaviours a person confirmed once
  • Test assets: plain test code in git, owned by you
  • Run history: every result and timing, kept

Execution

  • Sandbox: your app plus fresh data, deleted after the run
  • Runners: Playwright, Appium, k6, ZAP, axe
  • Evidence: video, traces, network and backend logs

Model provider

  • Small model: navigate, classify, summarise
  • Medium model: write tests, triage, fix
  • Large model: plan risk, review, hard calls
  • Your own key: optional, or a private endpoint
Proofline data flow. Companion to the build plan and the concept. Worker model sizes and the stack are proposals.
